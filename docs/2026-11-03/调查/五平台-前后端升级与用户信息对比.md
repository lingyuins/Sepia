### 1.3 部署形态

- magpie：桌面 App（Wails）/ `magpie web` 浏览器页 / `magpie serve` 服务 / TUI；官网独立 Cloudflare Worker。
- new-api：单进程（Go 静态二进制 / Docker `calciumion/new-api` / Electron 桌面）。
- metapi：Node 服务（Docker/Zeabur/Render/K3s）+ Electron 桌面 + VitePress 文档站。
- sub2api：Go 服务 + PostgreSQL + Redis（Docker / goreleaser 二进制 / K8s?），前端 Vue 构建。

## 2. 升级方案

### 2.1 对比表

| 维度 | octopus | magpie | new-api | metapi | sub2api |
|---|---|---|---|---|---|
| 应用内自更新 | **有**（POST `/api/v1/update`） | **有**（内置更新器，自动） | **无**（仅“检查更新”提示） | 桌面有(electron-updater)；服务端无 | **有**（UpdateService） |
| 更新源 | GitHub releases（`api.github.com/.../releases/latest`，可配 `update_url`） | `usemagpie.ai/api/latest`（`?channel=stable`） | GitHub Releases API（仅展示） | Update Center：GitHub Releases + Docker Hub；桌面 GitHub provider | GitHub releases（`Wei-Shaw/sub2api`） |
| 下载校验 | **无校验和/无签名**（仅 HTTPS） | **SHA-256** 强校验 | —（不下载） | Helm/镜像 digest；桌面 electron-updater | **SHA-256 + checksum 文件**；限 github/objects.githubusercontent；≤500MB |
| 替换/重启 | 下载 zip→解压→Win 改名 .old 替换/Unix 覆盖→重启进程 | mac 换整 .app（codesign 校验+回滚）/Win/Linux 换裸 exe；webReexec 重启 | — | Deploy Helper：`helm upgrade`+`kubectl rollout status`，失败 `helm rollback` | 下载→校验→替换→重启 |
| 自动更新 | ❌（仅手动点） | ✅（内建自动，多渠道） | ❌ | 桌面 ✅；服务端靠部署 | ❓按 buildType（source/release），手动触发为主 |
| 版本回滚 | ❌（仅 Windows 本次事务回滚） | ✅（保留旧包/失败回滚） | ❌ | ✅（Helm rollback） | ✅（允许回滚最近 3 个旧版本） |
| DB 迁移 | 启动版**版本化 AutoMigrate**（62 个迁移）+ 设置页可切库引擎（导出→建表→导入→重启） | 无中心 DB；各 Agent DB 只读 | 启动 GORM AutoMigrate（主节点）；**无版本化框架/无 downgrade**；旧 32 位额度 schema 硬门禁 | drizzle `migrate.ts`（SQLite）/ introspection 生成 DDL（MySQL/PG）+ `databaseMigrationService` 跨方言 | `ent/migrate` + `migrations/*.sql` |
| Docker 部署升级 | `docker compose pull && up -d`（容器内自更新不持久） | —（桌面） | 重拉镜像 `calciumion/new-api` | 重拉镜像 / Zeabur/Render 重建 | 重拉镜像 / goreleaser 二进制 |

### 2.2 逐平台要点
- **octopus**：`GET /api/v1/update` 查最新版、`POST /api/v1/update` 执行自更新；按 GOOS/GOARCH 下载 `octopus-<os>-<arch>.zip`→解压（zip-slip 防护）→替换（Win 先 `.old`）→`restartExecutable`；更新开始/成功/失败写系统通知；**无自动、无版本回滚、无包校验**（release 有 `md5.txt` 但更新器不用）。升级最稳妥走 Docker 换镜像或手动替换并核 md5。
- **magpie**：`internal/update` + `internal/gui/update*`；feed `api/latest`（stable/其它渠道）；下载强校验 SHA-256、断点续传+镜像兜底；macOS 校验 codesign TeamIdentifier、失败回滚；Win/Linux 换 exe、Smart App Control 预检被拒则回滚；桌面与 `magpie web` 内置自动更新器；`magpie serve` 无内建更新器。另有 **Agent CLI 自更新**（按安装来源）、**社区插件每小时自动更新**、**Bun 自动更新**（发布满 48h 采纳、保留回退）。
- **new-api**：**无应用内自更新**；前端仅查 GitHub Releases API 比较版本并弹“前往 GitHub”（`web/src/features/system-update`），不下载/替换/重启；后端无 updater。升级靠 Docker 镜像/Release 二进制/重装 Electron。DB 迁移靠启动 AutoMigrate（仅主节点），无版本化框架与 downgrade。
- **metapi**：三条链路——① **Update Center**（`/api/update-center/*`，15 分钟轮询 GitHub Releases/Docker Hub，事件+通知提醒；部署经 **Deploy Helper** 调 `helm upgrade`+`kubectl rollout status`，失败 `helm rollback`，Helper 独立服务 `:9850` + `DEPLOY_HELPER_TOKEN`）；② **Electron electron-updater**（仅打包桌面版，GitHub provider）；③ **Docker/Zeabur/Render** 手动重拉/重建。服务端容器版**无 app 内自更新**。
- **sub2api**：`UpdateService`（GitHub releases，缓存 TTL 20min）；下载限 `github.com`/`objects.githubusercontent.com`、HTTPS、≤500MB，有 `checksums.txt` 时校验 SHA-256，解压仅取 `sub2api` 二进制（Zip-Slip/体积防护）；**同目录原子 rename + 保留 `.backup`**，随后靠 systemd `Restart=always` 重启；**回滚**支持本地 `.backup` 与“比当前旧、最多 3 个”的在线版本（`ROLLBACK_VERSION_NOT_ALLOWED` 拒绝其它目标）；`buildType=source/release`（source 构建只提示 git pull，release 才显示更新/回滚）。DB 迁移为内嵌 SQL 启动前滚（advisory lock+checksum），回滚二进制不自动降级 schema。部署靠 Docker/goreleaser。

## 4. 关键差异总结（答题版）

1. **技术栈**：后端 —— octopus/new-api/sub2api 都是 Go+gin+gorm/ent；magpie 是 Go+Wails 本机网关（无中心 DB）；metapi 是 Node+Fastify+drizzle。前端 —— 只有 magpie 是**手写 JS 无框架**；octopus=Next 静态导出；new-api=React+Rsbuild；metapi=React+Vite(+Electron)；sub2api=Vue3+Vite。
2. **升级**：**自更新能力排序**：magpie（自动+多渠道+校验+回滚）≈ sub2api（校验+回滚）> octopus（手动自更新、无校验无回滚）> metapi（服务端靠 Update Center/Helm，桌面靠 electron-updater）> new-api（**无自更新**，仅提示）。
3. **数据库迁移**：octopus 有**版本化迁移**（62 个）+ 可切库引擎；metapi 按方言生成 DDL + 跨方言搬运；sub2api ent migrate + SQL；new-api 仅 AutoMigrate（无版本化、无 downgrade）；magpie 无中心 DB。
4. **用户可见信息**：octopus（14 模块，路由/运维最全）、magpie（本机 Agent/额度/路由轨迹）、new-api（计费/流量/排行最细）、metapi（多站点聚合监控+成本）、sub2api（订阅配额+运营后台最全）。
