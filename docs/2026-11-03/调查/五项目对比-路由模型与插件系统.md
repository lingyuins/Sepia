## 0. 五个项目分别在做什么（先分清形态）

| 项目 | 语言/框架 | 形态 | 一句话定位 |
|---|---|---|---|
| **octopus** | Go(gin) + Next.js | 单进程 Web 管理后台 + 推理网关 | 自建渠道/分组/号池的多供应商 AI 网关，带管理控制台 |
| **magpie** | Go(Wails) + 手写 JS | 桌面 App / 本机网关 / `magpie web` | 每个 Agent 的模型切换器，本机网关 + 多协议转发 + 插件生态 |
| **new-api** | Go(gin) + React(TanStack Router) | Web 网关（one-api 系） | 面向模型/应用/Agent 的 AI 网关，渠道+分组+计费+多协议 |
| **metapi** | TypeScript(Fastify) + React/Vite + Electron + drizzle | “中转站的中转站” | 把多个 New API/One API/Sub2API 等站点聚合成一个网关（relay for relays） |
| **sub2api** | Go(ent) + Vue3 + PostgreSQL/Redis | Web 网关 + 配额分发 | 订阅转 API、按订阅配额分发与账号池调度的网关 |

一句话区分：**octopus / new-api / magpie 是“面向模型供应商”的网关；metapi 是“面向网关/中转站”的聚合层；sub2api 是“面向订阅账号与配额”的分发网关。**

## 1. 请求路由模型对比（核心）

### 1.1 一句话概览

| 项目 | 路由抽象 | 策略是否可插拔 |
|---|---|---|
| octopus | `Group(5 模式) → GroupItem(渠道×模型,priority/weight) → Channel → Key/池账号` | 否（`GroupMode` 枚举固定 5 种） |
| magpie | `Provider/Group → Candidate(key/account×model) → Seat 策略` | **是**（`routes.Register` 注册表，插件可加策略） |
| new-api | `Ability(Group,Model,Channel,Priority,Weight) → Channel(多 key)` | 否（优先级分层 + 权重） |
| metapi | `站点 → 账号/账号Token → 路由(Route) → 渠道(RouteChannel) → 账号` | 部分（3 种 route 策略 + 每 token 路由决策） |
| sub2api | `分组(平台) → 账号池选择 → 账号` | 否（平台内固定调度 + 阈值/负载/粘性） |

### 1.2 逐项要点

**octopus**（详见 `octopus-路由模型调查.md`）
- 数据模型：`Group`（`Mode`/`MatchRegex`/`Condition`/`SessionKeepTime`/超时/`ThinkingMode`）、`GroupItem`（Channel+Model+Priority+Weight）、`Channel`/`ChannelKey`、`Pool`/`PoolAccount`。
- 三层独立选择：`GroupMode` 排“渠道+模型”；`Channel.KeySelectionStrategy`（cost/availability/speed/priority）选同渠道 key；`AccountPool.Strategy`（round_robin/random/least_loaded/ewma 默认）选池账号。
- 健康：熔断器 Closed/Open/HalfOpen（阈值 5、冷却 60s、指数退避、半开探测）+ 按 `(channel,key,model)` Key 冷却；错误四类 scope（None/SameChannel/NextChannel/AbortAll）；默认每候选 4 次 Key 尝试、全组 2 轮、总决策 64。
- 亲和：`Group.SessionKeepTime` 粘性（`apiKeyID:stickyRoutingKey`）。
- 智能：`Condition` 条件路由（选中组后的过滤）+ 自动分组 + **离线 AI 路由生成**。

**magpie**（详见 `magpie-路由模型调查.md`）
- 数据模型：`Provider`（Routing/Affinity/Sink/Fallback/AccountWeights）、`Group`（Members/Match/Rules/Classifier/Effort/FirstToken/Patience/Sink…）、`Member`、`candidate`、`Seat`。
- 策略：`routes.Strategy` 注册表；`Smart` 默认 + `order/rotate/usage/pace/weight/free/fast/drain/cheap`，`manual`（仅组）；**插件可注册新策略**（`plugins/rotation`）。
- 健康：按失败原因的 **Rest 阶梯**（credit 30m→7d、quota 到重置、rate 1min 翻倍封顶 30m、其它 1min 翻倍封顶 10m）+ Sink + FirstToken + Patience + HTTP/2 探测。
- 亲和：`Affinity` auto/session/turn/off/strict，持久化 `affinity.json`（512/24h，coldAfter）。
- 智能：`Rules` + `Classifier`（Jev 决策模型）+ `Effort:auto` + `auto/<model>` 发现组。

**new-api**（详见 `new-api-路由模型与插件调查.md`）
- 数据模型：`Ability{Group,Model,ChannelId,Enabled,Priority,Weight,Tag}`（`model/ability.go:18-26`）、`Channel`（含多 key，`channel.GetNextEnabledKey`）、`Token`/`User`/`Subscription`。
- 选渠道：`middleware.Distribute()`（`middleware/distributor.go:34`）→ `service.SelectChannelForRequest(...)`；顺序为 **pin → 渠道亲和 → priority 层级 → 层内按 weight 随机**（内存缓存 `group2model2channels` 或 DB `abilities` 两套等价实现，DEFAULT `Weight+10` 保证零权重也有机会）；`getPriority` 按 **重试次数选不同 Priority 层**（`ability.go:63-90`），`auto` 分组可跨组重试。
- 渠道亲和：`service.RecordChannelAffinity` / `controller/channel_affinity_cache.go`；token 的可用模型/分组限制（`TokenModelLimitAllows`）。
- 多协议：`relay/` 的 chat/claude/gemini/responses/image/embedding/rerank/mjproxy 等 handler + `relay/channel/*` 适配器 + `relaykit/`。
- 计费/订阅：`relay/request_billing.go`、`model/pricing*`、`model/subscription.go`、`controller/channel-billing.go`。
- 特点：经典 one-api 式“按 model+group 找 Ability 候选、按 priority 分层、weight 加权”，无独立“命名策略”抽象。

**metapi**（详见 `metapi-路由模型与扩展调查.md`）
- 聚合模型：`sites`（platform 可为 new-api/one-api/veloera/one-hub/done-hub/sub2api/orcarouter/openai/claude/gemini/codex/gemini-cli/antigravity）→ `accounts` → `accountTokens`；`tokenRoutes`（按 `modelPattern`，带 `modelMapping`/`decisionSnapshot`/`routingStrategy`）→ `routeChannels`（account+token，带 `priority`/`weight`/`successCount`/`failCount`/`consecutiveFailCount`/`cooldown*`）；`oauthRouteUnits`/`oauthRouteUnitMembers` 处理 OAuth 组合。
- 路由决策：`src/server/services/tokenRouter.ts`（144KB 核心）`selectChannel/selectNextChannel/selectPreferredChannel/explainSelection`，按 `tokenRoutes` 的 `routingStrategy` = **weighted（默认）/round_robin/stable_first**（`routeRoutingStrategy.ts`）；支持强制通道（tester 头）、决策快照、可解释选择；`normalizeModelAlias` + 精确/glob/`re:` 模型匹配。
- 健康/失败：`SiteRuntimeHealth` + breaker（乘子降权）、`filterRecentlyFailedCandidates`、`routeCooldownService`、`channelRecoveryProbeService`、`accountHealthService`、`proxyChannelRetry`/`proxyRetryPolicy`/`proxyFailureJudge`、`firstByteTimeout`。
- 模型发现/成本：`modelService`（discovery）、`modelPricingService`（referenceCost）、`modelAvailabilityProbeService`、`modelAnalysisService`；站点 `globalWeight`/账号 `valueScore`/`unitCost`/`balance` 参与“成本最优”。
- 亲和：token 级会话粘性 + `session-binding` + `downstreamClientContext`。

**sub2api**（详见 `sub2api-路由模型与插件调查.md`）
- 数据模型：ent schema 的 `account/group/channel/api_key/subscription/user/proxy/usage`；`domain/platforms.go` 定义平台（anthropic/gemini/openai/codex/antigravity/grok/bedrock/composite…）。
- **两套调度引擎**：通用 `GatewayService`（Anthropic/Gemini）按 **模型路由 → 会话粘性 → 优先级/负载(EffectiveLoadFactor)/LRU → 抢并发槽 → WaitPlan 排队**；OpenAI 高级调度器按 **previous response → 母账号 → 会话粘性 → 加权 Top-K**。候选来自 Redis 调度快照（outbox 重建），miss 回源 DB。
- 路由层次：Composite 分组按“显式路由→账号模型归属→内置模型识别”解析平台/上游模型；渠道映射、账号映射是三层不同映射。
- 失败/限流：`failover_loop*.go`（同账号重试或换号，已写流内容/断连则停）、`ratelimit_service*.go`、`overload_cooldown`、`error_passthrough*`、`upstream_protocol_routing*`、`proxy_fallback`。
- 订阅/配额：`subscription_*.go`、`user_subscription*`、`billing_*.go`、`pricing_service`、`openai_quota_*`、`account_quota_*`；并发槽 `concurrency_service`、临时禁调 `temp_unsched`、负载因子 `account_load_factor`。

### 1.3 路由模型差异小结
1. **抽象**：octopus 是“组内渠道选择”；magpie 是“候选+可插拔策略（Seat）”；new-api 是“Ability 优先级/权重”；metapi 是“站点→路由→渠道→账号”的聚合决策；sub2api 是“平台分组→账号池调度”。
2. **可插拔性**：只有 **magpie** 的策略是运行时注册表；octopus/new-api/sub2api 都是固定策略族；metapi 有 3 种 route 策略但可做每 token 决策。
3. **健康语义**：octopus 熔断器状态机；magpie 按原因 Rest 阶梯；new-api 优先级分层重试 + 自动禁用；metapi 冷却+健康探测；sub2api 限流分类+阈值+临时禁调。
4. **亲和/粘性**：octopus `SessionKeepTime`；magpie 五档 Affinity；new-api Channel Affinity Cache；metapi token 级会话粘性；sub2api sticky session。
5. **成本/额度**：magpie（额度/钱包/信用一等公民）、metapi（成本最优/定价探测）、sub2api（订阅配额窗口）最重；octopus/new-api 以计费为主。

## 2. 插件/扩展机制对比

### 2.1 一句话概览

| 项目 | 是否有插件系统 | 机制/形态 | 隔离方式 | 市场 |
|---|---|---|---|---|
| octopus | **有** | WASM（Extism/wazero）事件插件 + 自带 UI | 进程内 WASM 沙箱（内存/超时/payload 限额） | 无（后台上传 .zip/.octopkg） |
| magpie | **有（多套）** | OpenCode provider 插件(Bun) + Go 内置插件(pluginrt) + JS 网关中间件(moejs) + 页面/面板 + tool(MCP) + pi | Bun 子进程 / 网关进程 moejs / 窗口 iframe 沙箱 | **有**（market.json+registry+npm+GitHub） |
| new-api | **有** | JS 插件引擎（`pkg/jsplugin`，moejs `Calcium-Ion/moejs` + `MoeForge/moego`）+ 内置任务插件（sora/veo/kling…）+ 插件协议端点 | 同进程 JS 引擎（`DefaultCallTimeout=5s`、并发 8，受宿主限制） | 无（内置 embed + 管理端） |
| metapi | **无通用插件系统** | 靠适配器/注册表扩展：platforms、transformers、siteDetector、platformDiscoveryRegistry | —（编译期 TS 模块） | 无 |
| sub2api | **有** | HashiCorp go-plugin（gRPC 子进程）`.s2plugin` 包，manifest+capabilities+签名/校验和 | 独立子进程 + gRPC + 校验和/签名信任 | 无（管理端上传安装） |

### 2.2 逐项要点

**octopus**：`internal/plugin/`；`manifest.json`（host_api/id/events/permissions/http_origins/timeout/memory/instances/ui/config_schema）；事件钩子 `relay.request.before_route`、`relay.route.filter`、`relay.request.before_upstream`、`relay.response.before_send`（仅非流式）、`relay.completed`、`channel.health.changed`、`pool.account.changed`、`notification.created`、`http.rpc`、`plugin.migrate`；宿主能力 `kv/secret/http/notify/log`；`/api/v1/plugins/:id/ui-bundle` + iframe 三重隔离 + `/api/v1/plugins/:id/rpc/*path`；安装仅 admin 上传 zip、SHA256、无签名/市场。

**magpie**：约 8 类（provider/agent/middleware/gateway-hooks/page-panel/tool/builtin/pi）；三条运行路径（Bun 宿主 / 网关 moejs / 窗口 iframe）；网关六个扩展点（observer/strategy/middleware/masker/tool/budget，含 fail-open/fail-closed）；页面沙箱 token 化；有市场与 Bun 运行时管理。详见 `magpie-插件系统调查.md`。

**new-api**：
- JS 插件引擎 `pkg/jsplugin`（`engine.go`/`registry.go`/`routing.go`/`fetch.go`/`json_state.go`），用 `Calcium-Ion/moejs`（JS 引擎）+ `MoeForge/moego`（配套库），同步 ESM、**无 import/无动态代码**，`DefaultCallTimeout=5s`、并发 8。
- 插件 meta（`registry.go:86-110`）：`apiVersion/key/name/version/models/channelTypes/baseUrl/allowedHosts/upstreams/fetchMode/routes/protocols/usageSchema/auth/requiredCapabilities`；核心 hook `buildSubmitRequest/parseSubmitResponse/parseTaskResult`（per-task 另有 buildQueryRequest 等）。
- 内置**任务/媒体插件** `plugins/tasks/{alibaba,doubao,google,hailuo,jimeng,kling,sora,sunoapi,vertex-ai,vidu,xai}/plugin.js`（11 个，`plugins/embed.go` 注册）；上传插件是 `source` 字符串（≤8MiB）+ 可选 icon，而非 zip/npm。
- 两种参与 HTTP 路由的方式：**`meta.routes`** 注册插件自有原生 URL（submit/query/dynamic）；**`meta.protocols`** 认领/接管宿主协议（OpenAI Responses/Image/Video 等端点，`router/task-plugin-protocol-router.go`）。Registry 分 factory/override/activeOverride/disabledFactory 四层 + 不可变 `RoutingGeneration`，30s 轮询快照、原子发布。
- 权限不是声明式 ACL，而由宿主强制：URL 限于 BaseURL/`allowedHosts`、文件只给 `FileReference`、任务快照≤1MiB、SSRF/重定向/计费由 Go 控制。

**metapi**：**没有通用插件系统**。扩展靠 `src/server/services/platforms/`、`platformDiscoveryRegistry.ts`、`siteDetector.ts`、`transformers/{openai,anthropic,gemini,canonical}`、`proxy-core/providers|surfaces|capabilities`。即“新增一个上游平台=写适配器/转换器并注册”，编译期扩展。

**sub2api**：
- 包形态：`.s2plugin` = ZIP（`manifest.json` + `signature.json`(ed25519) + 按 `goos-goarch` 的原生可执行文件 + 静态 UI）；`PluginManifest` 字段 `schema_version/id/name/version/requires{sub2api,plugin_protocol,transport_api,ui_bridge}/capabilities/runtimes/ui/files(SHA-256)`。安装限大小/文件数、拒路径穿越/符号链接、逐文件验哈希、验签（生产默认禁未签名）。
- 运行：**HashiCorp go-plugin over gRPC**，宿主 `exec.CommandContext` 拉起原生子进程，`SecureConfig` 校验 SHA-256；`plugin_runtime.go` 做 `GetInfo/Health/ValidateConfig/ApplyConfig/TestConfig` 与双向流 `Forward`；`plugin_manager.go` 管安装/启用/禁用/配置/健康、`reconcileLoop`、按账号 ID 稳定分桶的灰度 `rolloutPercent`、UI asset token。
- 能力：当前**仅** `openai.oauth.outbound_transport.v1`（platform=openai、account_type=oauth）；HostService 提供 `KV*`（Redis）、`ListAccounts`（非机密视图）、`ResolveOutboundIdentity`（短期 access token/headers/proxy，不含 refresh token）。
- 与路由的真实关系：**核心调度器先选出 Account，之后**才把该账号的出站 HTTP 请求交给插件（`RoundTripOpenAIOAuth`）；未命中走内置 `HTTPUpstream`。插件**不替换账号调度器**；绑定插件不可用时 **fail-closed**，不静默回退。子进程不是 OS 沙箱（继承服务用户权限），故仅能装可信发布者包。
- 另有 `internal/managementmcp`、`internal/securityaudit` 管理与安全扩展面。
- 与 octopus/magpie 差别：sub2api 用**独立 gRPC 子进程**（发布/代码边界，非安全沙箱），octopus 是进程内 WASM 沙箱、magpie 是 Bun 子进程+Go 内置+JS。

### 2.3 插件/扩展机制差异小结

| 维度 | octopus | magpie | new-api | metapi | sub2api |
|---|---|---|---|---|---|
| 语言 | 任意→WASM | JS/TS、Go | JS（moejs） | TS（编译期） | 任意（gRPC 二进制） |
| 运行位置 | 主进程内(WASM) | Bun 子进程/网关内/窗口 | 主进程内(JS 引擎) | 主进程内(编译期) | 独立子进程(gRPC) |
| 隔离强度 | 强（WASM 限额） | 中（子进程+iframe） | 中（同进程，限资源） | 无（同进程） | 强（进程+校验和/签名） |
| 扩展点 | relay 钩子 + UI + RPC | provider/strategy/middleware/tool/page… | 任务/媒体协议 + 出站传输 | 平台适配/转换器 | 出站传输 + 管理/安全 |
| 市场 | 无 | 有 | 无 | 无 | 无 |
| 参与路由 | 可裁剪候选(before_route/route.filter) | **可注册路由策略** | 可声明模型/协议/路由 | 无（编译期） | 可提供出站传输能力 |

- **sub2api**：gin；`/api/v1/*` 后台 + 网关入口（`/v1`、`/v1beta`、`/anthropic`?、`/mcp` 等，见 `internal/server/routes`）；前端 Vue3（`frontend/src`）。

## 4. 总览：五个项目最关键的差异（答题版）

1. **定位差异**：octopus/magpie/new-api 是“模型供应商网关”；metapi 是“网关的聚合层（relay for relays）”；sub2api 是“订阅配额分发网关”。
2. **路由抽象**：octopus 分组渠道枚举、new-api Ability 优先级权重、sub2api 平台账号池、metapi 站点聚合路由、magpie 候选+可插拔 Seat 策略。
3. **可插拔**：只有 magpie 的路由策略是运行时注册表；others 固定策略。
4. **插件隔离谱系**：WASM 进程内（octopus）→ JS 进程内（new-api）→ Bun 子进程+Go 内置（magpie）→ gRPC 独立子进程（sub2api）→ 无通用插件（metapi）。
5. **市场**：只有 magpie 有插件市场；others 都是管理端/内置安装。
6. **健康/亲和**：magpie 的额度/速度/价格/亲和语义最丰富；octopus 熔断器最“状态机”；sub2api/metapi 更偏“账号健康+冷却+配额”。
